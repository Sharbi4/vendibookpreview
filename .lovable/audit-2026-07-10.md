# Vendibook Functional Audit — Phase 1 Report (2026-07-10)

Scope: static contract audit + read-only data reconciliation.
Method: DB introspection, schema diff against UI/edge-function code, log analysis.
Nothing was mutated. All findings are evidence-backed with counts.

## 🔴 P0 — Digest email pipeline is completely broken (single biggest issue)

Last 30 days, `email_send_log` for the three digest templates:

| template | sent | failed | dlq |
|---|---:|---:|---:|
| host-daily-digest | 0 | 2,570 | 514 |
| shopper-daily-digest | 0 | 825 | 165 |
| host-weekly-digest | 0 | 555 | 111 |

All rows fail with the same Mailgun response:
`400 {"type":"invalid_request","title":"Invalid request body","message":"Invalid request body"}`
after 5 retries → moved to DLQ. **No digest has been delivered to any user in at least 30 days.**

Non-digest templates are healthy (`welcome`, `listing-published`, `sale-completed-seller`, `new-message`, `support-reply`, `stripe-onboarding-nudge`, `listing-draft-nudge`, `generic-notice`, `featured-payment-receipt` — 100% sent).

Root cause is almost certainly a template-payload shape mismatch inside `send-daily-digests` / `send-host-weekly-digests` (they hit the Mailgun API directly rather than going through `send-transactional-email` — different envelope, and it's producing an invalid multipart body). Needs source read + one fix.

**Impact:** hosts and shoppers stopped receiving daily/weekly summaries silently. Retention impact.

**Action:** approve a targeted fix in Phase 2 for `supabase/functions/send-daily-digests/` and `send-host-weekly-digests/`, plus a one-time DLQ purge (or leave in DLQ for forensic review).

## 🟡 P1 — Duplicate rows per email send inflate all counters

For every healthy template, `pending` row count exactly equals `sent` row count (e.g. `welcome` 31/31, `listing-published` 74/10-shown, `new-message` 5/5). This means `email_send_log` writes a new row on enqueue and another on delivery instead of updating the existing row by `message_id`. Not blocking, but every dashboard/metric that counts by status is doubled.

**Action (optional):** patch the send pipeline to `UPSERT` on `message_id`, or accept that "sent" = final state and filter out `pending` rows older than 1h.
