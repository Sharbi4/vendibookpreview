- Live inventory uses the existing published/published_at/deleted_at/moderation/unlisted/title-exclusion rules, `listing_purchase_state`, and `sale_action_state`, plus committed sale exclusions. No production fixtures or outreach were created.

- RLS reads restricted to existing protected admin role. Clients have no direct insert/update/delete privilege on lead/draft/audit tables; mutations use authenticated admin-checked RPCs. No public PII endpoints. Atlas-private page marker added.
- No send endpoint or transport. UI labels drafts as not sent. `send` RPC action fails. Messenger drafts/approvals remain blocked without a sanctioned connection.

## Muse inference (not Facebook messaging)

Server function: `meta-muse-draft`, actions status/matches/template/muse. Calls only POST `https://api.meta.ai/v1/responses`, model `muse-wonder-1.0`, `reasoning: {effort: "high"}`, server bearer `META_MODEL_API_KEY`.

Contract follows owner-specified reference: https://dev.meta.ai/docs/overview/. The accessible official overview did not expose a full response schema during investigation; successful authenticated inference/response shape is **not verified** without the rotated key. Parser supports output_text and output/content/text; invalid response fails closed.

The adapter intentionally constrains Muse to validated phrase IDs rather than unrestricted prose. This is a limited but safe Muse-assisted draft: only intent/category/match count/approved phrases enter the model, never name, contact, lead free text, account data or private evidence. Listing titles and canonical links are appended locally. Model cannot introduce links, amounts or factual claims. There is no automatic fallback to another provider. Deterministic templates are separately labeled and explicitly selected.

Admin JWT/user and protected role are checked server-side. An atomic advisory-lock rate limiter permits 10 inference attempts/admin/hour, fails closed, with 20-second timeout and sanitized errors. No raw provider responses/errors, tokens or lead PII are logged. Inference/approval are separate and neither generates BuyerMatch activity or invokes existing outreach services.

## Blockers / safe operating limits

1. **Compromised credential**: revoke/rotate the previously pasted actual credential at Meta. Never recover/reuse it. Store replacement in Project Settings → Secrets as `META_MODEL_API_KEY`; none is currently configured. Secret listing contains 101 entries including managed/duplicate names; if adding reaches the environment cap, remove only confirmed unused secrets first. This implementation changed/deleted no secrets.
2. **Muse proof**: after rotation, an authorized admin must check inference using minimal nonprivate input and confirm response shape. Configured state remains explicitly “configured · inference unverified”, not connected.
3. **Admin end-to-end verification**: existing authorized admin must exercise create → match → template → edit → approve/reject → reload audit; no real outreach needed. Admin browser access was unavailable here.
4. **Facebook Page/Graph/Messenger** is NOT Muse inference. No Page OAuth, Page token, permission grant, webhook or traffic enabled by this phase. Existing catalog/conversions credentials are not evidence of messaging permission.
5. **Future sanctioned Page setup**: verify current official Meta app-review/business/Page requirements; configure business app OAuth, least-privilege Page permissions (such as pages_show_list/pages_manage_metadata/pages_messaging where currently required), server-only Page tokens; evidence of owned/authorized Page and granted scopes is mandatory. Do not use personal account login/tokens or scraping. Use a separately secured webhook: deployed callback first, user-shared verification secret, app-secret-backed X-Hub-Signature-256 validation before processing, strict schema/size validation, durable event/message-ID deduplication, private storage and audit. No webhook scaffold was enabled because security configuration is absent.
6. **Future sending phase** needs explicit approval, recipient-specific Page-scoped identity and inbound/consent proof, current messaging-window/policy checks and permitted purpose at send time, do-not-contact suppression, template/version approval, deduplication/idempotency, delivery acknowledgment and accurate failed/sent states. Generic consent is not Messenger eligibility. Never bulk send; never infer sent from approval.
7. Approval remains a point-in-time review, not a reservation. Date/availability changes after approval require review again before any future transport. No payment flow was modified.
8. Location scoring reuses existing city/state parser; approval conservatively requires city or two-letter-state form for ambiguous free-text locations. ZIP-only is unassessed, not geocoded. Vendor-space matching groups vendor lots via existing helper, but approval conservatively requires exact category due to current RPC check; vendor-lot drafts require specific category until that mapping is expanded. No live vendor inventory exists today.
9. No automatic import of existing private leads, BuyerMatch campaign activation, outreach logging, Page ingestion or email transport. This is authorized manual intake, review and draft preparation only. Lead/draft reads currently rely on API result limits; paginate before exceeding the default 1,000-row result cap.

Frontend was **not published**. No Facebook automation/scraping, outreach, changes to auth/payment settings, or fake production leads.
